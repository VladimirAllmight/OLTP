# PL/SQL: повышение зарплаты сотрудникам в `EMPLOYEES_COPY`

## Описание задачи

Данный PL/SQL-скрипт работает с таблицей `EMPLOYEES_COPY`, которая создаётся как копия таблицы `EMPLOYEES`.

Скрипт выполняет следующую логику:

1. Удаляет таблицу `EMPLOYEES_COPY`, если она уже существует.
2. Создаёт новую таблицу `EMPLOYEES_COPY` на основе таблицы `EMPLOYEES`.
3. Выбирает ровно 6 первых сотрудников из списка самых высокооплачиваемых сотрудников.
4. Определяет отделы, в которых работают эти 6 сотрудников.
5. Для каждого найденного отдела ищет сотрудников, занимающих самую низкооплачиваемую должность именно в этом отделе.
6. Повышает зарплату найденным сотрудникам на 15%.
7. Выводит результат в виде таблицы через `DBMS_OUTPUT.PUT_LINE`.

Итоговая таблица вывода содержит следующие колонки:

```text
FIRST_NAME    LAST_NAME     JOB_ID        SALARY(old)    SALARY(new)
```

---

## Используемая таблица

Скрипт работает с таблицей:

```sql
EMPLOYEES_COPY
```

Она создаётся на основе исходной таблицы:

```sql
EMPLOYEES
```

Команда создания копии:

```sql
CREATE TABLE employees_copy AS
SELECT * FROM employees;
```

Таблица `EMPLOYEES_COPY` нужна для того, чтобы не изменять данные в оригинальной таблице `EMPLOYEES`.
---

## Как работает скрипт

### 1. Включение вывода в консоль

В начале используется команда:

```sql
SET SERVEROUTPUT ON;
```

Она нужна для того, чтобы можно было видеть результат работы команд:

```sql
DBMS_OUTPUT.PUT_LINE(...)
```

Без этой команды вывод в консоль может не отображаться.

---

### 2. Удаление таблицы `EMPLOYEES_COPY`

Первый PL/SQL-блок удаляет таблицу `EMPLOYEES_COPY`:

```sql
EXECUTE IMMEDIATE 'DROP TABLE employees_copy';
```

Используется `EXECUTE IMMEDIATE`, потому что команда `DROP TABLE` является DDL-командой и внутри PL/SQL должна выполняться через динамический SQL.

Если таблицы не существует, возникает ошибка Oracle:

```text
ORA-00942: table or view does not exist
```

Для обработки этой ошибки используется:

```sql
PRAGMA EXCEPTION_INIT(table_exists, -942);
```

Если таблица не найдена, программа не завершается с ошибкой, а выводит сообщение:

```text
Таблица copy_employees не существует.
```

Важно: в сообщениях лучше писать `employees_copy`, чтобы название совпадало с реальным названием таблицы.

---

### 3. Создание копии таблицы

Второй PL/SQL-блок создаёт таблицу `EMPLOYEES_COPY`:

```sql
EXECUTE IMMEDIATE 'CREATE TABLE employees_copy AS (select * from employees)';
```

Здесь также используется динамический SQL, потому что `CREATE TABLE` — это DDL-команда.

Если таблица уже существует, возникает ошибка:

```text
ORA-00955: name is already used by an existing object
```

Она обрабатывается через:

```sql
PRAGMA EXCEPTION_INIT(table_exists, -955);
```

---

### 4. Выбор 6 самых высокооплачиваемых сотрудников

В основном PL/SQL-блоке сначала выбираются отделы, в которых работают первые 6 сотрудников из списка самых высокооплачиваемых.

Используется запрос:

```sql
SELECT DISTINCT department_id
FROM (
    SELECT department_id,
           ROW_NUMBER() OVER (ORDER BY salary DESC, employee_id) AS rn
    FROM employees_copy
    WHERE department_id IS NOT NULL
)
WHERE rn <= 6;
```

Здесь:

- `ORDER BY salary DESC` сортирует сотрудников по убыванию зарплаты;
- `ROW_NUMBER()` нумерует сотрудников после сортировки;
- `WHERE rn <= 6` оставляет только первые 6 строк;
- `DISTINCT department_id` убирает повторяющиеся отделы.

Важно: используется именно `ROW_NUMBER()`, поэтому выбираются ровно 6 сотрудников.  
Если у 6-го и 7-го сотрудника одинаковая зарплата, 7-й сотрудник всё равно не попадёт в выборку.

Например:

| Место | Сотрудник | Зарплата |
|---|---|---|
| 1 | A | 24000 |
| 2 | B | 17000 |
| 3 | C | 17000 |
| 4 | D | 14000 |
| 5 | E | 13500 |
| 6 | F | 12000 |
| 7 | G | 12000 |

Сотрудник под номером 7 не учитывается, потому что нужны только первые 6 строк.

---

### 5. Почему используется `DISTINCT department_id`

Если среди 6 самых высокооплачиваемых сотрудников несколько человек работают в одном отделе, этот отдел должен быть обработан только один раз.

Для этого используется:

```sql
SELECT DISTINCT department_id
```

Например, если в топ-6 попали сотрудники из отделов:

```text
90, 90, 100, 60, 60, 80
```

После `DISTINCT` останется:

```text
90, 100, 60, 80
```

То есть отделы `90` и `60` не будут обработаны повторно.

---

### 6. Поиск самой низкооплачиваемой должности в конкретном отделе

Для каждого отдела из списка выполняется отдельный запрос.

Фрагмент:

```sql
WHERE e.department_id = :d1
```

означает, что сотрудники ищутся именно в текущем отделе.

Минимальная зарплата также ищется именно внутри этого же отдела:

```sql
SELECT MIN(salary)
FROM employees_copy
WHERE department_id = :d3
```

То есть логика такая:

1. Берётся конкретный отдел.
2. Внутри этого отдела находится самая маленькая зарплата.
3. Определяется должность `JOB_ID`, у которой встречается эта минимальная зарплата.
4. Всем сотрудникам этого отдела с найденной должностью повышается зарплата.

---

### 7. Как определяется низкооплачиваемая должность

Используется условие:

```sql
GROUP BY job_id
HAVING MIN(salary) = (
    SELECT MIN(salary)
    FROM employees_copy
    WHERE department_id = :d3
)
```

Это значит:

> выбрать такие `JOB_ID`, у которых минимальная зарплата совпадает с минимальной зарплатой по всему отделу.

Например, есть отдел `50`:

| Сотрудник | JOB_ID | SALARY |
|---|---|---|
| Ivanov | IT_PROG | 5000 |
| Petrov | IT_PROG | 6000 |
| Sidorov | ST_CLERK | 3000 |
| Smirnov | ST_CLERK | 3500 |

Минимальная зарплата в отделе — `3000`.

Она принадлежит должности `ST_CLERK`.

Значит, зарплата будет повышена сотрудникам отдела `50`, у которых:

```sql
JOB_ID = 'ST_CLERK'
```

---

### 8. Повышение зарплаты на 15%

Новая зарплата считается так:

```sql
ROUND(e.salary * 1.15, 2)
```

То есть старая зарплата умножается на `1.15`.

Например:

```text
10000 * 1.15 = 11500
```

Функция `ROUND(..., 2)` округляет результат до двух знаков после запятой.

---

### 9. Защита от повторного повышения при одном запуске

В коде используется ассоциативный массив:

```sql
TYPE t_updated_emp IS TABLE OF BOOLEAN INDEX BY PLS_INTEGER;
v_updated_emp t_updated_emp;
```

После повышения зарплаты сотрудник запоминается по `EMPLOYEE_ID`:

```sql
v_updated_emp(r_emp.employee_id) := TRUE;
```

Перед повышением выполняется проверка:

```sql
IF NOT v_updated_emp.EXISTS(r_emp.employee_id) THEN
```

Это нужно, чтобы в рамках одного запуска PL/SQL-блока один и тот же сотрудник не получил повышение дважды.

Важно: эта защита работает только во время одного запуска блока.  
После завершения блока массив очищается из памяти.

---

### 10. Что будет при повторном запуске

Если запустить только основной PL/SQL-блок повторно, то сотрудники могут снова получить повышение, потому что массив `v_updated_emp` создаётся заново и ничего не помнит о предыдущем запуске.

Однако в данном скрипте перед основным блоком таблица `EMPLOYEES_COPY` удаляется и создаётся заново из `EMPLOYEES`.

То есть при полном запуске всего скрипта:

1. старая `EMPLOYEES_COPY` удаляется;
2. создаётся новая копия из `EMPLOYEES`;
3. повышение применяется заново к свежей копии.

Оригинальная таблица `EMPLOYEES` не изменяется.

---

## Почему используется динамический SQL

В скрипте динамический SQL используется через:

```sql
EXECUTE IMMEDIATE
```

и через динамический курсор:

```sql
OPEN c_emp FOR v_sql USING ...
```

Динамический SQL нужен, потому что имя таблицы хранится в переменной:

```sql
v_table_name VARCHAR2(30) := 'EMPLOYEES_COPY';
```

Поэтому SQL-запросы собираются как строки:

```sql
'SELECT ... FROM ' || v_table_name || ' ...'
```

Это позволяет при необходимости заменить имя таблицы в одном месте, не переписывая все SQL-запросы вручную.

---

## Основные переменные

| Переменная | Назначение |
|---|---|
| `v_table_name` | Название таблицы, с которой работает скрипт |
| `v_sql` | Строка с динамическим SQL-запросом |
| `v_departments` | Коллекция отделов, найденных среди топ-6 сотрудников |
| `c_emp` | Динамический курсор для выборки сотрудников |
| `r_emp` | Переменная-запись для хранения одной строки сотрудника |
| `v_updated_emp` | Массив для защиты от повторного повышения сотрудника за один запуск |

---

## Вывод результата

Результат выводится через:

```sql
DBMS_OUTPUT.PUT_LINE(...)
```

Сначала печатается заголовок таблицы:

```sql
FIRST_NAME    LAST_NAME     JOB_ID        SALARY(old)    SALARY(new)
```

Затем для каждого сотрудника выводятся:

- имя;
- фамилия;
- должность;
- старая зарплата;
- новая зарплата.

Пример вывода:

```text
FIRST_NAME     LAST_NAME      JOB_ID             SALARY(old)    SALARY(new)
---------------------------------------------------------------------------
Diana          Lorentz        IT_PROG                4200.00        4830.00
Luis           Popp           FI_ACCOUNT             6900.00        7935.00
```

---

## Сохранение изменений

В конце основного блока используется команда:

```sql
COMMIT;
```

Она сохраняет изменения в таблице `EMPLOYEES_COPY`.

Если нужно протестировать скрипт без сохранения изменений, можно заменить `COMMIT` на:

```sql
ROLLBACK;
```

Или временно закомментировать `COMMIT`.

---

## Важные замечания

### 1. Оригинальная таблица `EMPLOYEES` не изменяется

Все изменения выполняются только в таблице:

```sql
EMPLOYEES_COPY
```

Исходная таблица:

```sql
EMPLOYEES
```

остаётся без изменений.

---

### 2. Минимальная зарплата ищется внутри конкретного отдела

Да, код ищет минимальную зарплату именно в том отделе, который был выбран среди отделов топ-6 сотрудников.

За это отвечает условие:

```sql
WHERE department_id = :d3
```

---

### 3. Один сотрудник не повышается дважды за один запуск

За это отвечает массив:

```sql
v_updated_emp
```

Но эта защита не сохраняется между разными запусками скрипта.

---

### 4. Если нужна защита между разными запусками

Если нужно, чтобы сотрудник вообще никогда не повышался повторно при следующих запусках, нужно создать отдельную таблицу-журнал, например:

```sql
CREATE TABLE salary_raise_log (
    employee_id NUMBER PRIMARY KEY,
    raise_date DATE DEFAULT SYSDATE
);
```

И перед повышением проверять, есть ли сотрудник в этой таблице.

---

## Итоговая логика работы

Кратко алгоритм можно описать так:

```text
1. Удалить EMPLOYEES_COPY, если она существует.
2. Создать EMPLOYEES_COPY как копию EMPLOYEES.
3. Найти первые 6 сотрудников с самой высокой зарплатой.
4. Получить список их отделов.
5. Для каждого отдела:
   5.1. Найти минимальную зарплату в этом отделе.
   5.2. Найти должность JOB_ID, связанную с этой минимальной зарплатой.
   5.3. Найти сотрудников этого отдела с данной должностью.
   5.4. Вывести старую и новую зарплату.
   5.5. Повысить зарплату на 15%.
6. Сохранить изменения через COMMIT.
```
